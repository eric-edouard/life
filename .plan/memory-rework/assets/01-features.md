Research for the ticket Everything Life does for him today (9 Nov 2026).

Method: read from code and docs only (`AGENTS.md`, `docs/architecture.md`, `docs/tasks.md`, `docs/operations.md`, `docs/status-reads.md`, `docs/SCHEMA.md`, `docs/use/`, `apps/server/src/host/`, `apps/server/src/memory/`, `apps/mac/`). Nothing from the owner's data dir was opened. Paths are relative to the repo root. "(unverified)" marks what the code in this repo does not settle.

Every connector tool is built in `apps/server/src/host/http/mcp.ts` and calls the same function as the CLI (`bun life memory ...`, `apps/server/src/host/command.ts`). Read answers are plain text (`asData`, `apps/server/src/memory/words.ts`) or JSON text (status reads). Each call is logged as `mcp.call` with its tool, arguments, cited ids and the caller's agent claim.

Common layers behind most reads: `apps/server/src/memory/who.ts` (`readPeople`: truth + corrections + people-inferred), `apps/server/src/memory/ledger.ts` (`stateOf`, the one rule for hidden/retired/replaced), the index `LIFE_STATE_DIR/memory/index.sqlite` (`apps/server/src/memory/index-rows.ts`, `index-writer.ts`), and local days from `memory/zones.jsonl` (`apps/server/src/memory/zones.ts`).

## Surprises and gaps worth knowing

- Counts: 16 connector reads plus the instructions (17 rows); 4 write rows (`correct_memory` is 3 rows by kind family, plus `change_todo_item`, `tell_life`); 2 events rows; 12 page-surface rows; 11 mail and notification rows (3 are agent-side outside the repo); 5 app rows; 28 "Other" rows.
- The "daily Today" and weekly mails, and the daily triage, are not in this repo: they are scheduled tasks that consume the connector reads (`read_day`, `read_places_visited`, `read_open_todo_items`, `read_chats`, `search`, `correct_memory`). The rebuild must keep those reads' shapes, or change them in the one batched reconnect.
- Open items' "shown at most twice" rule is fed by the connector call log (`mcp.call` ids), not by any memory layer. Rebuild must keep the log or replace the rule.
- Appointments reach him only through his calendar; `read_day` does not list them and there is no connector tool for them.
- Situations and personas are visible only on a person page (and situations in `search`); area pages have neither, and a person without a page has neither.
- The `fact_check` connector enum offers true/partly/false only; "outdated", "skip" and undo exist only in the CLI `rate` and in `ratings.jsonl`.
- Edits to page files and `truth/` by hand are a feature (`keep-mine`, `not-important`, validate), not only an input.
