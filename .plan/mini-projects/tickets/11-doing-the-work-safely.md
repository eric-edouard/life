# Doing the work safely

## Question

How the agent works on the user's real things: a small sample first, batches, the user's yes before anything is deleted or changed, undo (trash before delete), and what Life's code enforces versus what rests on the agent (the send guard blocks only sends).

## Answer

Decided with the owner on 28 Nov 2026.

- **A small real part first, then batches:** after "Build it", work on the user's real things starts with a small part
  done for real and shown; then batches. A batch that deletes or overwrites gets their yes (a card); additions don't.
- **A restore point, always:** before any change, a copy, an export or a restore log; deletes go to a trash where one
  exists; the done page offers undo.
- **Enforcement:** Life can't see an agent's file operations; the playbook and the review before "done" hold the rule,
  and it is written down as a known limit (SECURITY.md).
