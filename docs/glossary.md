# Glossary

Reference: every name Life uses for one of its concepts, with what it means. One name per concept, the same in the
docs, the app, the email, the connector and the code. A name that is not here is a plain English word.

**Word** is the name in code and stored data today. **Planned** is a decided rename that hasn't landed yet: until it
does, code and stored data use the Word, and the PR that lands it moves the new name into Word. Stored values and
their formats are in [SCHEMA.md](SCHEMA.md).

## People

| Word | Means | Planned |
|---|---|---|
| owner | The one person whose life Life holds. Stored as `person:me`. In the app and user docs, "you". In prompts and what they write, his name: `{{owner}}`, filled by `readOwnerName` (his `called` in `truth/`, else his name's first word), never a pronoun. | |
| memory language | The language his memory is written in, asked at the first run beside his name: the `memoryLanguage` setting, `{{language}}` in prompts. Absent: English. Quotes stay as said; topic tags stay English. | |
| action step | One named step of an action as it passes, passed with its time or still to come (`ActionStep`; `recorded`, `chat_checked`, `handed`, `confirmed`; a matter marked done: `todo_items_ticked`, one per item, or on a Drop (a your move's, or a whole matter's) `todo_items_removed`; a new matter's Start: `goal_saved`, then the start stages; the phone's own `connection_retry`), sent as a `notifications/progress` message after the plan (`report`, `mcp-tool.ts`). Not a matter step, not a processing step, not a night step. | |
| agent | One of the owner's assistants: a registered agent the desk runs, or an app paired as one (`bun life pair <name>`), known by its grant's agent claim. Nothing branches on a name. The word stored for an agent's source is `AGENT_WORD`, `agent`. | |
| pairing | How an app is approved on the connector: `bun life pair <agent>` prints a code; the app's grant (its tokens and refresh record) carries that agent's name as its agent claim, which is how the connector knows the agent (`authInfo.extra.agent`). A grant with no claim (a plain app, `bun life pair` alone) reads only. `--link` prints the link the phone app opens (`lifelog://pair?life=<origin>&code=<code>`), with the voice server's `url` (`<origin>/voice`) and the phone's device `token` once the voice server minted it, so one QR pairs both. | |
| speaker | Who said a turn in a recording. | |
| split group | Clean sampled turns separated from a job's speaker label by voice; recognized turn rows keep the group, which supplies no identity or evidence. | |
| A stranger | The owner's answer for a voice he does not know: a stranger (status `unknown` with `basis: owner` in the voice server). The voice naming never guesses it: its guess is stored `unknown` at `weak` whatever the model said, and the score counts how many such voices a hidden run guessed a person or him (`ownAnswerOf`, `sources/voice-speakers.ts`). Not "not relevant". | |
| not relevant | The owner's answer for a voice he won't name: maybe someone he knows, so that voice is not asked about again and is never a stranger's reference (status `not_relevant`). Not "A stranger", which makes a stranger. | |
| recheck | A voice the owner named as a person that the voice server, judging without that voice's own conversations, hears as another person on at least half of its sampled turns. Only the voice eval counts them; nothing offers one to him or marks it (`rechecked` is no longer written). | |
| sample | A voice embedding of one clean recorded turn, with its model and revision; no extra audio. Unnamed samples are nobody's evidence. | |
| profile | A person's owner-attributed voice evidence, represented by one exemplar per conversation of clean clips. | |
| likeness | A voice's mean cosine to a person's closest profile exemplars; a score, not an identity or evidence. | |
| bench answer | What the owner says of a turn in the voice bench's review (one answer there names every turn of a voice's card): a person, nobody he knows, several people, not a person, or a skip. Several people and not a person leave the scoring. Kept in the bench's own file until `bench apply` sends it to the voice server as his correction. | |
| sender | Who wrote a message in a chat or mail. | |
| detail | A field about someone that his directory or his Contacts already holds (birthday, where they live, work, family, each handle its own), shown in their `now` (`memory/details.ts`), less the handles their reach already opens; a work line names the organization of his directory its company is, a family line the person its name resolves to (`ref`, `detailRefOf`). Never stored apart from where it lives; anything else about them is a page line. | |
| reach | How to reach someone, per app (WhatsApp, iMessage, Telegram, Mail, then a call): the accounts his directory, his Contacts and their own 1:1 chats give, each with the link that opens it (`chatLinkOf`, a call's `tel:`), its title the name they showed there, else Contacts' label ("Mobile"), newest exchange first (`reachOf`, `memory/reach.ts`). Worked out when read, never stored. Not a detail. | |
| read_people_and_organizations | The connector's read of the people and organizations Life knows: with no name, the list ordered by closeness (with `query`, its matches and `others`); with a name, one of them, `now` and `latest` as JSON and the other parts as prose (`person`, `memory/read-person-page.ts`; `personNowOf`, `memory/person-now.ts`). Not a search of what was said (`search`), not their messages (`read_chats`). | |

## The agent's work

| Word | Means | Planned |
|---|---|---|
| answer result | What `answer_check` returns (`answerWithResult`, `host/answer-result.ts`): the lines written (`done`), what `changed`, the `send`'s outcome (`sent`, `not_sent` with `canRetry`, `may_have_gone`), `doneSeen` (a look's outcome, `seen` or `not_found`, with Life's words; `seen` also `paid`: the amount, `value` and `currency`, and `seenAt`), the `asker` and whether it was told (read once, never waited for), and `start` (a new matter's Start: the desk's start result as `change_registered_agent` gives it; null otherwise). Composed from what each store says, never stored. Not a decision's `answered` line. | |
| agent mark | The logo of the program a registered agent runs in, shown beside it on his phone (`RuntimeName.mark`): Claude's for Claude Code, OpenAI's for Codex, from their makers' kits, in one colour; a terminal for any other or when the ask names no agent (`Check.agent`). Not a mark (his words to Life). | |
| push level | How a push interrupts him, Apple's `interruption-level`: passive (Notification Center only, no sound), active, or time-sensitive (`levelOf`: urgent, with no deadline or within 3 hours of it). Set by the Mac; the phone never changes it. | |
| push id | `pushId`: a check's opaque id for a push, an HMAC of its ref under a key that stays on the Mac (`pushIdOf`, `memory/checks.ts`). The phone matches it against the inbox (the push's `pushId` field); it is never the ref. | |
| ask | The owner's words handed to the desk: a spoken ask ("hey Life"), his word about a registered agent, or his complaint. A ledger entry of kind `ask`, read by the desk alone. | |
| call ended | The desk event `call.ended`: a picked-up call matching an agent's wait ended and the voice server holds its words. Facts only; once per agent and call; a call with no recording queues nothing. Not `message.received`, which a call's start is. | |
| recording cut | A read of a recording bounded to a span of instants, such as a call's exact `at` and `until` (`fetch`'s `at`, `until`): the turns that overlap it (`OVERLAPS`), a turn crossing an edge kept to its words wholly inside by the voice server's word timings, said left out without them (`memory/recording-cut.ts`). Not a unit's day bounds, not a read part's span. | |
| event channel | What a wait's `channels` names besides a message app (`EVENT_CHANNELS`, `host/event-channels.ts`): its name, the event it queues, the event quantities its events hold, whether they hold a point (`hasPoint`), and its read, which the desk makes on its beat over a fixed look-back only while a wait names it. Today `payments`, `places` and `github_activity`. Not a source | |
| payment booked | The desk event `payment.booked`: a payment his money app holds, matching an agent's wait. Its facts: its amount, in EUR too (`eur_out` or `eur_in`, by the sign), its currency, whether it is spending, the money app's category, and when (`at`, `day`), never its merchant or note; once per agent and payment | |
| stay arrived | The desk event `stay.arrived`: an arrival at a place (a stay that began within the read's 48 hours), matching an agent's wait by its point within `radius_m` of the wait's `latitude` and `longitude` (`radius_m` is `read_places_visited`'s `radiusM`, 100 by default) or by `text_matches` on `arrived <place>`. Its facts: when (`at`, `arrivedAt`) and where (`latitude`, `longitude`), never the place's name; once per agent and stay, though one real arrival can give more than one stay | |
| event quantity | A number an event channel's event holds, by name (a payment's `eur_out` or `eur_in`), that a wait compares with `quantity`, `above` and `below` | |
| wide net | What wakes an agent on a matter besides its own wait (his word of 18 Nov 2026, `desk/matter-net.ts`): a new message from one of the matter's people, or a new message or recording of his pendant whose meaning is close to the matter's name, goal, next step or newest steps (`netOf`), by the Mac's embedder at `CLOSE_AT`. Queued as the desk event `matter.related` (its facts, and why: `person` or `meaning` with its similarity), never its words. Not a placement in the matter: the nightly matters step decides that. | |
| event | MCP's word (its Events extension, `events.ts`): what an agent waits for, polled with its own filter and cursor (`events/poll`): `message.received`, and for a paired agent its own decisions' follow-through, `decision.answered` (his answer), `decision.lapsed` (unanswered at its deadline: it takes `onSilence`) and `decision.withdrawn` (a draft card he answered in its chat himself: it reads the chat again), from the cursor `request_decision` returns. Computed when polled, never stored. Not `SourceEvent`, a source's record in code, nor a calendar's event (the Past calendar's, an appointment's: the calendar's own word, in `google-calendar.ts`, `calendar-events.ts`, `appointment-events.jsonl`). | |
| mark | His words to Life, to keep: a promise that the unit is always read and every fact extracted, each at its own importance, not a statement that it matters (`marked` on the unit). Made by "hey Life" in a recording (Life's own wake, `LIFE_WAKE`; also a spoken ask), a message to himself, or `tell_life`. | |
| spoken ask | His "hey Life" span, recorded as an ask of the desk with its conversation (`isSpokenAsk`), which the desk asks of the main session, its receipt its thread entry (`ask_key`, `receiveSpokenAsks`); or his words through Ask Life the main session hands to one agent (`tell_agent`), with the assignment they go `to`: never routed by meaning, there or its agent's open assignment, else (its agent ended) the Personal agent's (`toldPlaceOf`), whose receipt is its `ask.spoken` event row, one across every agent. Not his word about a registered agent, not his complaint. | |
| told-life, `tell_life` | What he tells Life in a chat: the connector's tool appends his words verbatim to `memory/told-life.jsonl`, read back as the source `told-life` ("Told Life"). Refused for an agent's token. | |
| bridge | A program that links one of his messaging accounts to his local Matrix homeserver, so Life can read LINE, Instagram, Messenger and LinkedIn (`bun life bridge`, `NETWORKS`, docs/use/bridges.md; WhatsApp's is only for sending, its reading stays the Mac app's). A network is copied from Beeper Desktop while Beeper holds it and its bridge is not linked yet (`copierOf`). Not the connector (the MCP server). | |
| integration | Anything he turns on that needs something of him to work: a source, a messaging network, the AI, voice, the pendant, the phone's way to the host (`integrationsNow`, `host/integrations.ts`; its terms live on the registry entry that already exists). Its state is `integrationHealthOf`'s, served as `/status/integrations` and the connector's `read_integrations`. Not the connector (the MCP server), not an output or an add-on (settings with no step for him). | |
| requirement | One thing an integration takes of him, in the order he meets it: a permission, a sign-in, a key, a balance, an install or a pairing (`Requirement`, `records/integration.ts`); whether it is done is worked out when read, never stored. Not a card's need (`Need`, `memory/needs.ts`), not a matter's `needs_you`. | |
| app keys | The two keys of his own that a network's bridge needs in its config before it starts (Telegram's `api_id` and `api_hash` from my.telegram.org), named on its `NETWORKS` entry (`appKeys`: their config paths, which are secret, and where to get them); one still equal to the example config the bridge writes is pending (`needsAppKeys`), and `bun life bridge link` asks for it. Not a model provider's key, not a login. | |
| login flow | The bridge's way of signing a network in that his phone and the CLI use, by its id (`NETWORKS`' `loginFlow`, required: LINE's email and PIN, Instagram's, Messenger's and LinkedIn's cookies, Telegram's and WhatsApp's phone number). Not the bridge's other flows (the CLI's `link <network> <flow>` can still name one), not a login (the session the bridge keeps). | |
| Beeper | Beeper Desktop, his messaging app: Life copies a network from its store (`copyBeeper`) until its bridge is linked (LINE allows one session: his word of 18 Nov 2026 moves LINE onto Life's own bridge, which replaced his 6 Nov word to keep it in Beeper). Never its API or MCP: only its store keeps what a deletion blanks long enough for the archive's copy. | |
| auto-add permission | The owner's standing permission for Life to add the to-dos he says aloud to his to-do list (`setAutoAdd`; its ledger lines are `auto_add`). | |

## The desk

| Word | Means | Planned |
|---|---|---|
| desk | The part of Life that starts and wakes his registered agents (`apps/server/src/desk/`, its own helper, store and lock; off until the `desk` setting). Holds one rule about what an agent may do, the send guard. Not the watcher or a night step. | |
| send guard | The hook that refuses an agent of his own Life a send outside a card's draft (his word of 20 Nov 2026): a connector's send, a send command, resend to others, an invitation to others, a messaging site or app, a GitHub post off the repos he listed or unsigned, his Life connector's writes on any server but its `desk` door (`SEND_RULES`, `desk/send-guard.ts`), run before each shell and MCP call (`SEND_GUARD_HOOK`, `send-guard-hook.ts`; in pi, inside its process by Life's pi extension, `desk/runtimes/pi-extension.ts`, which also gives pi the door and Life's model provider, its routing on every request). Partial: it reads a call's text (SECURITY.md). Not a permission ask, nor Life's own send (the draft send). | |
| subagent | A session an agent of his own Life on pi hands one task to (`subagent`, `desk/runtimes/pi-subagent.ts`): inside the same pi process, on Life's extension with no door and no connector, so the send guard holds; its usage counts in the agent's turn. Not a registered agent: the desk never sees it. | |
| web search | What an agent of his own Life on pi searches the web with (`web_search`; `web-search/`): the providers his `desk.webSearch` names, else Life's chain (Tavily, Serper, Brave, Perplexity's Search API), each with his key, the next asked when one fails; each paid search's price (`core/prices.ts`) is kept on its turn apart from its models (`turn.search_usd`), model spending's `web_search` kind. | |
| agent post | A comment, issue or review an agent of his own Life posts itself with `gh`, only on a repo he listed (`desk.agentPostRepos`) and ending with `AGENT_POST_SIGNATURE`; the GitHub source reads one as his agent's (sender `agent`), never his. Not a card's draft. | |
| matter of his own | A matter that involves someone he knows (`isKnownToHim`: his directory, a person or an organization, or his Contacts; one Life inferred only once his word named it) or holds an open step he said himself (`isOneOfHis`, `memory/read-matters.ts`). Only a matter of his own is handed out; one made only of an unknown sender's words waits for his own Start. Not every matter he is in. | |
| hand-out | The desk giving a matter itself to the agent that takes it (`agentForOf`), on the top running matter of his ranking that passes `handOutGateOf` (`memory/read-matters.ts`: a `do` next step, its project underway, its direction not due, not dismissed, not held, one of his, an agent takes it) (`handOutOf`, `desk/hand-out.ts`; `isHeldOf`); a matter whose projects are all parked ranks last, within `desk.handOut` (`cardsWaiting` of his agents' cards in his inbox, `aDay`; absent: off). It starts no agent: it opens an assignment, by `desk` (`assignment.opened_by`), whose first turn asks one card, not a plan. Not an agent he asked for, nor a new matter check (that is his Start). Five words share its root, each its own: hand-out (this); handed over (`handed_over`, a stopped agent replaced by a new start on its subject, under registered agent); an event handed to a turn (its delivery to an agent, `handed` in the desk's event rows); handed work (under its own line); and a handoff (a one-off project made of an ask, under its own line). | |
| registered agent | An agent the desk keeps: an id `agt_…`, its name (`agent.name`, his to set; its sessions are titled "Agent: <name>", the main session's and the caretaker's, until he names them, "Agent: Ask Life" and "Agent: Caretaker"), its assignments, a brief, a model (and effort) or its runtime's default from the desk's settings (`modelOf`), its sessions. Created only on his word: a project's (a one-off project's when it is written, `openOneOffProject`), or the Personal agent; the desk also registers the Personal agent for a confirmed arrival no matter's agent takes when none stands, and the main session and the caretaker from its start. Its sessions and runtime may change; its id does not. It ends when its last open assignment closes or is folded away. Active (a turn running or waiting), `stopped`, `handed_over` or `ended`. Several agents may share a project (his word of 20 Nov 2026); the oldest takes its matters (`agentForOf`); a matter has at most one active agent. When he starts an agent on the subject of a stopped one, the stopped agent is `handed_over` to it in that start, over at once and listed nowhere; resuming it is refused. A stopped agent beside an active one on its project stays stopped and resumable. Not a session. "What are my agents doing?" is `readRegisteredAgents` (`host/registered-agents.ts`; the connector's `read_registered_agents`). | |
| agent health | Whether a registered agent, or the desk, does its job (his word of 22 Nov 2026): `fine`, `attention` (it works, something is off) or `broken` (it can't do its job until something changes), with why in plain words (`agentHealthOf`, `deskHealthOf`, `host/agent-health.ts`), worked out when read on `read_registered_agents`, never stored. An agent's reads its runtime's block, its turns, its events unheard, its session held open elsewhere and, for Claude, whether a session his Claude app lists sits in the Life Agents group (`readClaudeAppListing`; each fresh session is listed there once, `listInApp`); the desk's, whether it runs, its main session and caretaker, and the Life plugin. Only active agents are judged. Not the desk health rows of the nightly (`host/desk-health.ts`: where agents and matters drift apart). | |
| Personal agent | The one registered agent in role `personal` (`agent.role`, one active or stopped at most) that takes every matter no project's agent takes (`agentForOf`); its home is `<agentsRepo>/personal/`, made with a placeholder `AGENTS.md` until his rules are written. Started (`role: "personal"`) or marked (a re-point) on his word, or registered by the desk (`PERSONAL_BRIEF`, `desk/role-agents.ts`) for a confirmed arrival no matter's agent takes when none stands. Not a project's agent. | |
| assignment fold | Every matter sits with the agent that takes it (`agentForOf`): an open matter assignment another active agent holds moves to it, with its anchors, wait, times, events, notes file and cards, once its agent has no turn running (`foldAssignments`, `desk/matter-net.ts`, over `moveAssignment`); an agent left with nothing open ends, "folded into the <name> agent". Not a person fold (`foldsOf`). | |
| assignment | One subject given to one registered agent (`assignment` in the desk's store, `asg_…`): its anchors, its agent wait, its notes file (`notes_path`, in `desk.agentsRepo`), who opened it (`opened_by`: `owner` or `desk`), the matter chosen (`matter_id`: his Start's or the hand-out's), when, and how it closed (`closed_at`, `outcome`, `why_not_started`). Turns and queued events are an assignment's; its agent runs one turn at a time. `closeAssignment` (`desk/agent-actions.ts`, over `closeAssignmentRow`) is the one way one closes; which owns a card is `assignmentOfCard` (`host/desk-read.ts`), from the `card` row the desk wrote when it was asked. Not a session, nor a matter. | |
| holder | The agent of an open assignment (`assignment.agent_id`, changed only by `moveAssignment`): the one that works on its matter, and the one its cards are shown as asked by, in the inbox and in what wakes an agent (`cardOwnersOf`, `host/desk-read.ts`, over `assignmentOfCard`), whoever asked them. Not a card's asker (`Decision.agent`). | |
| agent move | His word moving work between his agents (`change_registered_agent` `hand_over`; a `move` row keyed by his ask, whose id the wire calls `move`, `desk/agent-moves.ts`): a **matter move** (one matter's assignment to a new agent of its own on another runtime, in the old agent's folder, named after the matter; or back to an agent he names) or a **runtime switch** (a whole agent to another runtime, its id and assignments kept). The old agent first writes its notes in one turn of its own session (cause `move_notes`, best effort within 10 minutes), then the holder changes in one transaction; a first turn that does not begin within 30 minutes rolls it back. Not the fold (Life's own rule), not `handed_over` (a stopped agent replaced by a new start), not an event handed to a turn. | |
| move phase | Where a move stands, worked out when read (`movePhaseOf`, `host/move-read.ts`), never stored: `notes` (the old agent's notes turns, `done` of `total`), `starting` (committed: the new holder holds it, its first turn not yet begun), `done` (that turn began), `failed` (refused, or rolled back: the old holder holds it, `reason` one sentence of `MOVE_REASONS`). | |
| session open elsewhere | An agent's session that a process outside the desk keeps open (his Claude app, Claude Code in a terminal), read from the process's live record (`readOpenSessionRecords`, `host/open-session-records.ts`: Claude's own, or Life's Terminal launcher's for pi): the desk never resumes it, so its wakes wait until that process lets go (`isSessionOpen`). Logged once per opening (`desk.session_open`) and shown on the agent while it waits (`sessionOpenIn`, `sessionOpenSince`, an amber line; his phone's row: "Paused: open in your Claude app", or "on your Mac" for pi in Terminal). Not an agent holding a matter (`isHeldOf`). | |
| continue on his Mac | His tap "Continue on your Mac" on an agent's page (`change_registered_agent` `continue_on_mac`, his app's token only): the desk opens the agent's session on his Mac (`continueOnMac`, `desk/continue-on-mac.ts`; pi's own interface in Terminal through Life's launcher, `desk/runtimes/pi-terminal.ts`, with Life's extension and so the send guard; Claude in his Claude app), refused while a turn runs ("Busy. Try in a moment"). It is then a session open elsewhere: its wakes wait, and resume by themselves once he leaves it: closed, or quiet 10 minutes (`hasLeftOf`, by the record's status and its time) when a wake is due, Life ends its holder (SIGTERM, `takeBackIfLeft`; his ruling of 22 Nov 2026: no button). What pi spends there, on Life's key, has no turn and is not counted in spending. Not the listing: every fresh Claude session sits in his app's sidebar once, in the background, with no process (`listInApp`, his ask of 26 Nov 2026), and typing there makes it open there the same way; in an agent's session the Life plugin approves his app's permission asks, as the desk's no-ask mode (`tool.check`). Codex has none yet. | |
| own assignment | An agent's assignment with no anchors: its listening (a project agent's project, `agent.project`; the Personal agent's, nothing). Every other assignment is a matter. | |
| assignment subject | What an assignment works on: one matter, held by its anchors (with the matter's id he chose, `matter_id`, only to settle a tie between matters sharing them: a re-group changes ids, never steps), or its agent's own listening (its project of `truth/`, `agent.project`, or the Personal agent's); exactly one. | |
| anchor | A matter step's id by which an assignment's matter is found (`anchor` table, by assignment): the step he named first, then the rest of its matter's steps, and its cards' subjects. A matter has at most one active agent holding it by an open assignment (`holderOf`). | |
| agent change | His word about a registered agent: start (on a matter: an assignment of the agent that takes it, his words its `said`; on a project, or `role: "personal"`: a new agent), stop (which also stops the turn under way, his yes of 20 Nov 2026), resume, re_point, rename, change_model (`AgentChange`). From a chat (`change_registered_agent`) it is an ask of the built-in agent `desk` (`DESK_AGENT`) with `after.agentChange`; the desk applies each once, in code (`desk/agent-changes.ts`), and writes what it did or why not (`agent_change` row). Not a `Change` of the to-do list. | |
| report line | One line a scheduled task or a session posts for the nightly report's Agents section (`bun life desk report-line`), one per source per day; shown in the next report. | |
| runtime | The program a registered agent's sessions run in (`claude`, `codex`, `pi`), behind one contract (`desk/runtimes/contract.ts`), implemented once (`sessionRuntime`, `session-runtime.ts`) over a connection: Claude Code and Codex over the Agent Client Protocol (`acp-runtime.ts`) with a runtime row each (`runtime-rows.ts`), pi over its RPC (`pi-runtime.ts`), pinned in Life and run on the memory's OpenRouter route. Claude's and Codex's CLI is found on the PATH less `node_modules/.bin` (`readProgram`), so the desk runs his CLI, never Life's pinned one. Each has `stop`, which ends the desk's own run of a session, never his app's process; a run not begun within the desk's begin limit (`BEGIN_WITHIN_MS`, 5 minutes, `agent-wait.ts`) is stopped. pi is the built-in one (`BUILT_IN_RUNTIME`): the default when his settings name none, and the **runtime fallback** (`desk/runtime-fallback.ts`): a start is refused only when pi can't run either, and an agent with no session yet whose runtime can't run takes pi for good at its wake (logged `desk.runtime_fallback`, said in its agent health); one with a session never switches (a session can't change runtime): his move does. | |
| start stage | One of the facts the desk writes while a new agent starts, in order: `desk_accepted` (the desk took the start: the `agent_change` row with an agent id and no error; a refusal stops here), `session_open` (the `session` row), `turn_begun` (`turn.begun_at`: the model's first update after the prompt, as the ACP runtime saw it, never a process alone). `change_registered_agent` (and `answer_check`'s Start on a new matter check) reports each as it appears and ends `started`, `not_started` (the agent is ended, why in `assignment.why_not_started`: its runtime refused, or its first turn ended or did not begin within the desk's begin limit) or `unconfirmed` (20 s). `goal_saved`, before them on a matter start, is the start's words saved as his `matter-direction` by `changeRegisteredAgent` itself (nothing when they already are his goal). | |
| runtime row | The data that makes the ACP connection a `claude` or a `codex` one (pi's is `PiRow`, `pi-runtime.ts`) (`Row`, `desk/runtimes/runtime-rows.ts`): the adapter's command and environment, the door's header, its no-ask mode (`mode`), a second Life's door-tool prefix (`onlyDoorPrefix`: the only asks approved; none: all are), its option names for model and effort, the session's link and how a session's state is read from the program's own files. A second Life's isolation is data in its row. Not a runtime (the contract). | |
| login environment | The variables of his login shell (his keys, his PATH), read by `readLoginEnv` (`core/proc.ts`) once per desk process and given only to an agent of his own Life, less its runtime's engine keys. Not Life's own secrets (Keychain, `.env`), and never logged or stored. | |

| Word | Means | Planned |
|---|---|---|
| read state | What one read of Life is on the phone (`ReadState`, Kit's `LifeConnector`): its last good value, when it was read, and what the latest try is doing. A screen shows `shown`: loading, loaded, empty, stale (a failed refresh after a good read), unreachable (the Mac is out of reach), failed or not paired. | |
| read flights | How the phone runs its reads of Life (`ReadFlights`, Kit's `LifeConnector`): one read of each kind at a time within a pairing, plus one more pass for every ask made while it runs, so an older read never lands last; a pass queued under an earlier pairing never begins, and the new pairing's reads make passes of their own. Not a cache, and not a retry. | |
| out of reach | When the phone cannot reach Life (`LifeConnection`, Kit's `LifeConnector`; `LifeStore.whyOutOfReach`): no network path, or the newest settled read of Life found no internet or the Mac out of reach, until a read asked later gets Life's answer. The app is then read-only: a tap on a screen acts on nothing (`refusedOutOfReach`), its controls are off, and every read screen says why above what it shows. Not a read's stale face, which says only that its own last try failed. | |
| answered cards | The cards his answers took out, with when Life confirmed each (`AnsweredCards`, Kit's `LifeConnector`), kept with the phone's reads: every screen leaves a card out of any read asked before its answer was confirmed (`LifeStore.answersNewer`); a read asked after wins. Kept until every kept read was asked after it (forgotten only at launch), and one pairing's: an answer begun under another adds nothing (`PairingGeneration`, the one test of a pairing for reads and answers). Not Life's record of the answer, which is the decision's. | |
| read version | `version` on a `read_inbox` or `read_matters` answer: a digest (`versionOf`, `host/inbox.ts`) of what it answers from: the inbox's whole list and how many are due today, the matters' answer; never of a key alone (a card can change under the same files' stamp, life#779). Passed back as `ifNot`, the answer is only `{version, unchanged: true}` while nothing changed; the inbox's order holds while its version does, so `after` (a card's ref) pages it. Not the cursor of the memory's changes (`read_memory_changes`). | |
| pushed card | A tapped push's card as the phone holds it (`PushedCard`, Kit's `LifeConnector`; `LifeStore.pushed`): the cached inbox's, else the one its notification kept if read from the Life paired now (`CardNotification.isOf`), else Life's read of its `pushId`, which no limit cuts off (`CardNotification.card`, the one door to a notification's card, for every answer from it too). The Inbox opens on it at once, its answers live, until a whole read asked after the tap says it is still open or gone ("Already answered…"); the pager shows the spinner while that read runs. Not a read of its own. | |
| paired life | The Life an answer was decided for (`PairedLife`, Kit's `LifeConnector`): its origin and its pairing generation, captured once at his tap (on a card, a notification's button or Send, or when he held it for Undo). Every try of that answer, a retry or a queued release included, goes to that origin with that Life's bearer, and none goes once another pairing began. Not the pairing link (`LifePairing`), nor the Life paired now. | |
| action state | Where one of his actions on Life stands on the phone (`ActionState`, Kit's `LifeConnector`): running with its steps, succeeded with its proof, or failed with the step, the reason and whether a retry is allowed. Only the server ends it. | |
| People tab | The phone's third tab: everyone Life knows (his directory's people and organizations and everyone with a page, `read_people_and_organizations` with no name), closest first by closeness level, the unjudged last, or A to Z; all, people or organizations (`PeopleList.groups`, Kit); beside it, or over it on a compact width or the open Duo upright (decision 93), one of them as a page from their `now`. A matter's people and the people an agent wakes on open their page (`AppRouter.open(party:)`); other parties the app draws do not yet. Beside the list the page on show is one of the rows on show, unless opened from elsewhere (`PeopleList.selectionOf`). Not his Contacts: the others Life has seen show only in search. | |
| page chain | A part read page by page on the phone (someone's `reach`, their `latest` paging back), as it stands (`PageChain`, Kit): the pages that arrived in order from the first, then the next to ask for, the one being read, the one that failed (asked again on Try again) or the end. A page is asked only once the one before it arrived. Not the server's paging, which only gives each page's next ref. | |
| page stack | A tab's page on show and what is pushed on it (`PageStack`, Kit; the People tab's in `AppRouter`): opening a page, even the one on show, starts it bare. Not the tab's list. | |
| design data | The made-up content the Kit tests decode with the phone's own models: one file per connector read in `apps/lifelog/fixtures/design/`, in the wire shape (an instant without a zone is the phone's own time), read by Kit's `DesignReplies`. Not `fixtures/wire/`, which Life's server tests write. | |
| frame map | Which screen state each designer's frame draws, joined by frame name: the designer's half (`frame-map.json` in the designer's folder: pose, size, picture, state) and the repo's (`frames.json` beside the design data: launch arguments and taps, or why a frame can't be reached). `bun run design:shots` reads both. | |
| frame spec | A designer's frame as text, for a model that cannot see the picture: its layout tree with each element's box in points, token names, text and states (`render_frames.py --spec`, in the designer's folder). `bun run design:export` writes the ones a task needs beside their pictures and the design pack; `bun run design:shots --compare` checks the app's accessibility tree against it. | |
| thread item | One ask or matter as the thread shows it, in one of its states: needs you, later, under way, waiting on someone, settled, queued, outdated, held, earlier draft, deleted for both, stopped (`ItemState`, `ThreadComponents.swift`; the grid is in the current spec). Not a matter step. | |
| under way | The state of an item while Life is doing it: a line of what, a small spinner (a still ring when the work is long), Undo while Life can still stop it. Not "waiting on someone". | |
| held | The state of an ask that waits behind another open ask into the same chat (`contests`): shown as a held separator with its line, never as a second open card. | |
| notice | A short block of Life's words about something that happened between items (a stop, a lapse, a limit): a line and, when there is one, one button. Not a card and not an ask. | |
| fix ask | The ask Life brings when something it needs from him is broken (a sign-in, a permission, a limit): one button that fixes it. Shown as a notice. | |
| sign in from the phone | His app's sheet that signs a network's bridge in, from a fix ask's sign-in option (`signsIn`: its bridge signed him out, or was added and never linked): one bridge login step at a time through the connector's `sign_in_to_network`, by the network's login flow; Life keeps none of what he types. Not his pairing with Life, not `bun life bridge link`. | |
| reaction | A mark on his bubble that Life or a person gave it (`Reaction`, `ReactionMark`). Not an answer and not a rating. | |
| rated | A reply he rated with the thumbs (`RatingRow`): kept as a label, never an action. | |
| edits | The quick changes a draft ask offers as chips (shorter, warmer, other words; `EditChips`): each is one tap, and the draft stays his to send. | |
| spending stop | The line a notice shows when Life stopped itself at the owner's spending limit; one button lifts it. | |
| aura | The coloured light along the phone's edge that says what Life is doing (`EdgeView`, `AuraSetting`), off until he turns it on with the halo settings' switch (`isAuraOn`, kept on the phone): ten colours, and per state (idle, you speak, working, no Mac) its speed, brightness, glow, blur, colour, lights and pool, with the border, the three turning lights and the rings; his halo settings (the `settings` block's `aura` key) tune every value and save them as the `aura` setting (`change_setting`). The pendant's own ring is separate. | |

## Folders

| Word | Means | Planned |
|---|---|---|
| owner data dir | The owner's data repo: `truth/`, `memory/` (`OWNER_DATA_DIR`, env `LIFE_OWNER_DATA_DIR`). No git remote, ever. | |

| settled day | A day whose stored zone derived lines never change, so its units keep their dates and ids: a day a record cites by a unit id, one on or after the first episode, a deferred day that holds units, and one neighbour each side (`settledDays`, `historical-zones.ts`). | |
| travel day | A derived-era day whose own sent mail shows the zone changing between its known neighbours (it names both the zone of the known day before and of the one after, and they differ), a clock change included (2023-10-30, Europe's DST switch). Deferred, with no units, until a source can tell which part of the day was where (`historicalZonesOf`). | |
| derived era | The days before his first zone record that has no `source` (`derivedEraEnd`, `historical-zones.ts`): the only days photo offsets and sent-mail Date headers may set, defer or gap. | |
| boundary zone | One layer of the code in fallow's checks (`.fallowrc.json`). | |
