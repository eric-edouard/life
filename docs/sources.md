# Data sources

Reference: what each source reads and how.

Every source is read-only. Each one is a file in `apps/server/src/sources/` that returns `SourceEvent`s with stable ids, so
reading twice never duplicates anything. What Life knows about a source is its descriptor in `apps/server/src/memory/sources.ts`:
its kind (agent, chat, mail, own_writing, repo, voice), its bounded reader, earliest available history, the `read_chats` default window, and what its ids say
(groups, handles). Adding a source is one more descriptor there, and its name in `SourceName` (`core/names.ts`). Raw data stays in its own app; Life keeps only ids and short quotes (and an ask's words, `docs/tasks.md`). Before any text reaches a model,
`apps/server/src/core/redact.ts` removes key blocks, card numbers, IBANs, long tokens and lines that look like passwords or codes.

Each chat and mail reader also names a message's files (`SourceFile`, `records/source.ts`: where it was met, name, type, and the
path when the file is on this Mac). One place, `showFiles` in `apps/server/src/memory/message-files.ts`, turns them into lines of the message,
such as `[photo IMG_2910.HEIC, described by Life: … | text: …]` or `[video clip.mp4, not on this Mac]`, so every memory
step, search and the connector see them. Each file on this Mac is read once into `memory/files.jsonl`: a document's text
(`textutil`) and a PDF's text layer (`pdftotext`) by code, a photo or a scanned PDF's first page (`sips`, as JPEG) by
the fast model (`prompts/files.v1.md`), 8 per call. Video and voice notes stay a tag. Originals stay in their app (or
the archive's media copy); Life copies none, and a description outlives its file.

| LINE, Instagram, LinkedIn, Telegram (bridged) | Life's archive of each bridge (`line.sqlite`, `instagram.sqlite`, `linkedin.sqlite`, `telegram.sqlite`), copied from the bridges' local homeserver (`docs/use/bridges.md`), or, for a network with no bridge on the Mac, from Beeper Desktop's store (`~/Library/Application Support/BeeperTexts/index.db`, read-only; LINE since 6 Nov 2026), each time from one of them (`copierOf`, `copyBeeper`) | `bridged.ts` | Same chat-day units as WhatsApp; a message deleted for everyone keeps its text, an edit reads as its last version. The chat is the Matrix room, named by the room or its other members; the sender is the network id in its bridge's ghost, or Beeper's contact id for what Beeper copied (so one person can have two handles there). Unit ids are `<network>:<room>/<event number>`. The homeserver keeps every event (`redaction_retention_period: null`), so a message deleted before a copy is still copied. Telegram has no bridge linked yet, so its source is off; turned on, Beeper would copy it with Matrix sender ids where its 30 Oct history holds phones, so map them first. `beeper.sqlite` stays on disk as the untouched original of the history moved into these archives on 30 Oct 2026; Life never reads it. |
| WhatsApp | The archive below, opened read-only; senders' phones from the Mac app's `ContactsV2.sqlite` (`@lid` ids) | `apps/server/src/sources/whatsapp.ts` | Same chat-day units as the bridged networks, and messages deleted for everyone keep their text and an edited message reads as its last version. Senders not in the address book stay `unknown`. |
| Message archive | WhatsApp Mac app's store, `~/Library/Group Containers/group.net.whatsapp.WhatsApp.shared/ChatStorage.sqlite`; the bridges' homeserver, `~/Library/Application Support/Life/bridges/synapse/homeserver.db`; Beeper Desktop's store for a network with no bridge | `apps/server/src/host/archive.ts` (the loop), `copyWhatsapp`, `copyBridged` and `copyBeeper` (`store` in each descriptor) | The one exception to "raw data stays in its own app": WhatsApp blanks a message deleted for everyone, and a bridge's network can too, so every 5 s Life copies new and changed messages into `~/Library/Application Support/Life/archive/`: `whatsapp.sqlite` (plus APFS clones of media) and one file per bridged network (text and attachments' metadata; for what Beeper copies, APFS clones of the media it cached, under `media/<network>/`). Each version is kept (original, edits, the blanked one). A WhatsApp call's details (its length, video or not; a protobuf in `ZWAMEDIAITEM.ZMETADATA`) are kept in `phone_calls`, each version once, since a call's row changes when it ends; a bridged network's calls are its bridge's notices ("Audio call ended", "Voice call (5m33s)"), read by the network's `callOf`, a start joined with its end. Every store is opened read-only. The homeserver keeps a deleted message's text until the archive copies it. Messages WhatsApp had already blanked before the first run, and ones it removes outright instead of flagging, cannot be recovered. `bun life archive deleted [days]` lists deleted ones from all. Closed, WhatsApp and Beeper receive nothing, so the archive opens a closed one hidden (`store.app` in its descriptor). |
| Note archive | Apple Notes' store, `~/Library/Group Containers/group.com.apple.notes/NoteStore.sqlite` (Core Data; bodies are compressed protobuf) | `copyNotes` and `readNotes` (`apps/server/src/sources/notes.ts`) | Notes overwrites a note in place, so every 5 s the archive keeps each new version in `notes.sqlite` (`versions`): the text, checklist lines marked `[ ]`/`[x]` (a tick is a change), and the attachments it holds (id, type, file in Notes' Media folder, Apple's OCR or table summary; no file copies). Every folder; shared notes included and marked; locked and not-downloaded notes skipped entirely. A version is saved once the note has gone 2 minutes without an edit. A note in Recently Deleted, marked deleted or gone from the store gets a deleted row (a restore is a new live row), except when more than 20 vanish at once or the store lists none (a sign-out). An iPhone edit reaches the store only while Notes runs on the Mac, so the archive opens it hidden when it is closed. Read back by `readNotes` (`notes.ts`) as one chat-day per note: each version in the window is a message showing what it changed (`+ `/`− ` lines, the first version whole, a deletion `[deleted the note <title>]`, a restore `[restored the note <title>]` and what changed since the last live version), the owner's own except in a shared note (sender `shared note`: a co-editor may have written it), with the attachments it added as files (`notes:<attachment id>`) and Apple's text of a table or scan as a line. Memory only, never the owner's words for actions. |
| iMessage and SMS | `~/Library/Messages/chat.db` | `imessage.ts` | Opened read-only. Newer messages keep text in `attributedBody`; the reader decodes it. Attachments from the `attachment` table, link previews left out. A 1:1 chat with no name of its own takes the name the owner's Contacts give its number or email (`contacts.ts`). |
| Phone & FaceTime | `~/Library/Application Support/CallHistoryDB/CallHistory.storedata`, copied read-only into `archive/phone.sqlite` (`calls`) by the existing archive loop | `copyPhone`, `readPhone` (`sources/phone.ts`) | Optional source `phone`, off unless enabled. Only `com.apple.Telephony` and `com.apple.FaceTime`; third-party calls stay with their own readers. Each scan keeps changed payloads by `ZUNIQUE_ID`, including late syncs; Apple deleting a row never removes its copies. The latest version reads as a `phoneCall` event in a call-only chat: a remote handle or the joined remote participant set (a group UUID alone does not establish a group). Contacts supply display names; raw handles go through the people resolver, never identity by name alone. Positive duration proves connection even with `ZANSWERED` unset; rounded to seconds, at least one. Zero duration with an unanswered flag means not picked up; otherwise no end seen. Types 1, 8 and 16 mean telephony, FaceTime video and FaceTime audio. [Parser schema evidence](https://github.com/novkostya/ios-backup-parser/blob/main/docs/schemas/calls.md). [History can be deleted](https://support.apple.com/en-ie/guide/phoneapp/phn33a31c85/mac) and [syncs through iCloud separately from backup](https://support.apple.com/en-gb/guide/icloud/mmc2662aa6e0/icloud); automatic pruning is unverified, so no fixed retention cutoff is assumed. |
| Contacts | The Mac's AddressBook databases, `~/Library/Application Support/AddressBook/` (its own and each account's under `Sources/`) | `contacts.ts` | Opened read-only. Each record with a phone or an email is read whole (`readContactRecords`): its name names handles (a phone by its last 9 digits, an email lower-cased) for the readers that carry a number alone; its birthday, work, addresses, relations and profiles are the details of the person one of its handles resolves to (`memory/details.ts`). Unreadable, the readers read as before. |
| Email, all accounts | Apple Mail's local store, `~/Library/Mail/V10/` | `mail.ts` | Covers every account in Mail (iCloud, IMAP, Exchange). Every MIME part with a file name is a file, in the `.emlx` or, for a partial one, in Mail's `Attachments` folder. Historical collection reads bounded months and saves searchable passages, excluding newsletters and Life's own mail. Search ranks the saved rows and shows the best 5 thread-days; it never scans raw mail. Message files are parsed once per process. Sent-mail raw Date headers also provide model-free historical zone offsets (see [zones](SCHEMA.md#zonesjsonl)). |
| Git commits | `git log --all --no-merges --numstat` in every repo under the `repos` setting's folder (worktrees folded into the main repo by `git rev-parse --git-common-dir`) | `git.ts` | Read-only. One unit per repo and day (`repoDay`, cut by `messageUnits` like a chat-day). A commit in two clones of one repo counts once, in a clone mapped to a project first, then the first by folder name. The owner's commits in every repo; in the repos of the owner's projects (`Project.repos` in `truth/projects/*.md`) other authors' too. The episodes step tags them (topics), code caps their importance at 1, so they are searchable and listed by `day` but never extracted. Lines leave out lockfiles, binaries and files changed by over 3,000 lines in one commit (generated). |
| Recorded conversations | lifelog's REST API (`/changes`, `/transcription-jobs/{id}/transcript`, `POST /search` for the exact words), owner device token as `LIFELOG_TOKEN` in `.env` | `lifelog.ts` | Reads only, except the owner's corrections `forward` sends. Units come from the store `bun life watch` keeps, the only caller of `poll` (so every `hey <agent>` is heard), which holds conversations and who spoke each turn when, never the words. A unit is one transcribed conversation's turns on one local day; its words are fetched when its day is read (episodes, extraction, `fetch`), never stored, and extraction keeps short quotes. lifelog's summaries are never read; a chapter unit stored before conversation-days stays as stored. |
| The agent's done tasks | Life's own ledger, `memory/ledger.jsonl` (`tasksOf`) | `agent-source.ts` | Kind `agent`. Stored history: no agent writes updates since 2 Nov 2026. One unit per task the agent closed done itself (its own last update, not the owner's tick in Reminders), dated when it closed: the owner's ask's words (the first 1,500 characters) and the agent's outcome, all one line by `agent:` + `AGENT_WORD`, never the owner's nor resolved to a person. Its own report, not checked by Life: extraction may read it as evidence of what was done, to close a loop it sees among its priors (one of its own episode, or one of the owner's own from its day or the day before, as for any unit), such as the to-do the owner's ask also left. Always read (importance at least 2), never searched as messages. |
| Screen Time | Apple's Biome streams, `~/Library/Biome/streams/restricted/` (SEGB files of protobuf records): `ScreenTime.AppUsage/local` (the Mac's app time, Screen Time's own, idle left out), `App.InFocus/remote/<device>` (the app in front on each iOS device that syncs to the Mac), `App.WebUsage/local` (Safari's websites); device ids and platforms from `~/Library/Biome/sync/sync.db` | `copyScreen` and `readScreen` (`apps/server/src/sources/screen.ts`) | Kind `screen`, activity like git: never extracted, importance 1 at most, never searched as messages. Biome prunes after a week or a few, so every 5 s the archive copies each new record into `screen.sqlite` (`events`), raw, each once by its key (a record an iPhone syncs late still lands). Read back as stints (an app until the next comes or it leaves, a website by its visit; the same one back within 2 minutes joined; the lock, home and sign-in screens, Finder, settings and Life itself left out, call screens kept), one device-day per device and local day: its time by app and website (a minute or more), then its stints of 5 minutes or more. Apps by bundle id, websites by domain, never an address or a page. The `devices` setting names each device; one left out shows its platform. The status card watches only devices still in use: of each platform Biome still syncs, the one heard from last (a retired phone turns nothing amber, his word of 9 Nov 2026). |
| Told Life | `memory/told.jsonl`, appended by the connector's `tell_life` | `memory/told.ts` | Off until `told` is in his `sources` setting. His words verbatim, marked; the question he answered, if any, reads as the assistant's line. |

`bun life archive whatsapp <folder>` fills missing message and call identities from a full older store without replacing archived versions or rewriting rows; sender phones use that folder's `ContactsV2.sqlite` when present, otherwise the Mac's, and missing media files are skipped.

Mail he sent only to his own addresses, and every message of a chat with himself, are marked: his words to Life, to keep.

The calendar is not a source: the agent reads it. Nor are his payments: with the `payments` setting, `read_day` and
`read_payments` read them from his money app (`money tx`, `apps/server/src/payments/`) and place each one in his day,
at read time; no model reads them. (The Past calendar and the appointments are Life's output, `docs/tasks.md`; of its
own events Life reads back only whether one is confirmed or gone.)
